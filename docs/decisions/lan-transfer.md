# 區網傳輸:同一份格式的第三種傳輸管道

**狀態:已決定要做,排在「macOS 詞庫驗證修好」之後。** 使用者 2026-08-09 提出:

> 「安卓版跟 iOS 版本因為屏幕太小不方便,可能還要增加一個局域網導入。
>  用戶不想用我們的方案,但是他想用自己的方案,就可以通過局域網訪問,
>  這個不是聯網的功能。」

---

## 這不是一個新功能,是一個新的傳輸方式

三件事要分開看:

| | 現況 |
|---|---|
| 匯出/匯入詞庫與設定 | Android 已完成,格式見 `docs/backup-format.md`。**macOS 做了但驗證沒過所以下架**(加了詞之後候選裡沒有那個詞) |
| 匯入自己的方案 | Android 已有「從檔案匯入」 |
| **區網傳輸** | 本文件。**是上面那份格式的第三種傳輸管道**(現有的是檔案選取器) |

這樣定義的好處:四端共用一套格式、一套守門,不會又長出一條各自為政的匯入路徑。
**手機螢幕小,用電腦的瀏覽器拖檔案進去,這是對的解法。**

## ⚠ 「這不是聯網」只對一半

資料確實不出區網,這跟「無聯網」的定位不衝突。**但它引入了這個專案目前完全沒有的
一類風險:對外監聽。**

現有的 `NetworkGate` 守的是**出去**的流量。區網伺服器是**進來**的 —— 咖啡廳、旅館、
辦公室的 Wi-Fi 上,**同一個網段的任何人都掃得到它**,而傳輸的內容是使用者的詞庫
(他打過的字)。

### 因此:獨立的開關、獨立的紀錄

**不可以混進現有那個連網開關。** 如果「連網開關是關的,但手機上有個伺服器在跑」,
使用者會覺得我們在騙他 —— 而整個定位建立在那句「開關關著,紀錄是空的,你自己看」。
兩件事語意不同,就要兩個開關、兩份紀錄。

## 規範性要求

1. **預設關閉,且只在那個畫面開著時執行。** 切到背景就關、逾時就關。
   **不是一個可以忘記關掉的開關。**
2. **一次性 PIN**,畫面上顯示,電腦端要輸入才連得上。
3. **畫面上顯示現在連著誰**(IP)以及正在傳什麼。
4. ⚠ **匯入的方案必須走跟方案市集完全一樣的守門** —— 壓縮檔防護(zip slip)、
   `SchemaPreflight`、Lua 沙盒。
   **這是最容易出事的地方:一條「本機的、所以安全」的匯入路徑,繞過了下載路徑上
   所有的檢查。RIME 方案裡有 Lua,匯入一個方案就是在執行別人的程式碼。**
5. **明講「同網段的人可能看得到」**,不要假裝它是加密的。HTTP over LAN 就是明文。

## 為什麼排在後面

macOS 的詞庫匯出**現在是壞的**(`apple/scripts/verify_user_dict.sh` 自己驗出來:
格式看起來對,但加了詞之後候選裡沒有那個詞,所以那一頁被下架)。

**區網傳輸是那份格式的傳輸層 —— 底下的東西還沒對,先做傳輸只會把一個壞掉的東西傳得更快。**

順序:
1. 修 macOS 的詞庫驗證(那一關變綠 = 詞庫頁上架)
2. 桌面端接上匯出/匯入
3. 行動端加區網傳輸
