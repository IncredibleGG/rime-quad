> 這份報告的每一個數字都來自**在模擬器上真的裝起來、真的打字、真的截圖量測**。
> 沒有一張圖來自網路。裝不起來的，我直接寫「裝不起來」，並附上崩潰堆疊。
>
> - 量測環境：AVD `rime_compete`（Pixel 6 profile，Android 15 / API 35，x86_64 +
>   `libndk_translation`，1080×2400，density **420dpi ⇒ 1dp = 2.625px**），port 5562。
> - 輸入目標：本專案自建的 `dev.rime.imetest`（`scripts/build_testapp.sh`）。
> - 量測方法：`adb exec-out screencap -p` 取原生解析度 PNG，再用 Python/PIL 對
>   截圖做「帶狀平均亮度 + 雙峰門檻」求鍵矩形。**px 誤差 ±2px（≈±0.8dp）**；
>   圓角以逐列掃描鍵左緣求得，誤差 ±2px。
> - 截圖存放於 `docs/reference/<competitor>/`（該目錄在 `.gitignore` 第 67 行，不進版控）。

## 0. 摘要：這一輪最值得記住的五件事

1. **我們的九宮格是 4 欄；三星是 5 欄，語燕也是 5 欄。**
   缺的那一欄是**左側標點欄**（`,` `。` `?` `!` …）。這一欄不是裝飾——它讓
   「打完一個詞順手點逗號」不必切層。見 §3.1。
2. **「1」的位置在三星與語燕都是「分詞」鍵，不是數字。** 我們放的是 `'`。
   語燕連 `重輸` 都有（三星也有），我們兩個都沒有。見 §3.1。
3. **語燕的左側標點欄在打字時會變成「拼音消歧欄」**（顯示 mi / ni / m / n / o
   讓你選這一串 T9 按鍵到底是哪個音節）。這是讀原始碼絕對想不到的互動，
   也是九宮格能不能用的關鍵。截圖 `yuyan/52-t9-candidates.png`。見 §3.3。
4. **語燕的設定有兩層：鍵盤內 12 宮格快捷面板（含「鍵盤高度」拖曳把手）+ App 內
   3 群組設定頁。** 「安裝即用」的體感就是這個面板給的，不是設定頁。見 §4。
5. **我們的「符」層會從 4 欄跳到 10 欄**（`ours/31-t9-symbol.png`），
   手指位置整個重來。語燕的 123 層維持 5×4，三星的符號層維持 7 欄的近似節奏。見 §3.4。

## 2. 「有沒有真的跑起來」——先講失敗的

這一節必須先講，否則後面的數字會被誤讀。

### 2.1 語燕最新版 v20260530.10：**畫面錯位，實質不可用**

裝得起來、IME 起得來、按鍵能按，但**鍵盤被畫到螢幕外面**：工具列出現在
y≈2136px（螢幕高 2400），下面四列鍵只露出第一列，其餘被螢幕底邊裁掉。

- 截圖：`yuyan/10-t9-default.png`、`yuyan/probe-land.png`（橫向也一樣錯）
- `dumpsys window` 顯示 IME 視窗 `Requested w=1080 h=2400`、
  `frame=[0,128][1080,2400]`、`gr=BOTTOM`、
  `Requested non-default-visibility types: navigationBars`
- 排除過的可能：換 host app（系統設定搜尋框也一樣）、關掉「全面屏鍵盤優化」
  改「普通鍵盤」、改 `wm size 1080x1920`、改 `wm density 160/240/320`、
  轉橫向再轉回直向、重啟 IME process。**全部無效，可穩定重現。**
- 我的判斷：這顆 APK `targetSdkVersion=36`（Android 16），跑在 API 35 上，
  很可能是 edge-to-edge / WindowInsets 行為對不上；也可能與 arm64→x86_64
  的 `ndk_translation` 有關（無法排除）。**這是「在這台 AVD 上」的結論，
  不代表在真機上不能用。**

### 2.2 因此語燕改用 **v4.3.3（2024-08-23，原生 x86，targetSdk 34）**

這一顆**完全正常**，所有截圖與量測都出自它。缺點是它比最新版舊約兩年：
最新版 README 宣稱的「雙拼七種」在 4.3.3 只有小鶴一種，
設定項也比最新版少（最新版我有把設定頁全部走過並記下項目，見 §4.2）。
**所以 §4 的設定清單來自最新版（它的 App 端是正常的，只有鍵盤畫面壞掉），
§3 的佈局與幾何來自 v4.3.3。這一點請務必記得。**

### 2.3 同文 Trime v3.3.11：**沒能跑起來，如實記錄**

Trime 的使用者資料目錄在 **`/storage/emulated/0/rime`**（外部儲存），
它的設定精靈第一步就是要 `MANAGE_EXTERNAL_STORAGE`（「所有檔案存取權」）。

（`logcat` 另有 `W/[main]: Skip starting rime`）

## 4. 語燕的設定組織（使用者兩次指名要看的部分）

### 4.1 Onboarding（最新版 App，正常）

三步，**沒有帳號、沒有網路、沒有教學頁**：

1. 隱私政策全文 + `同意` / `拒绝`（`yuyan/02-launcher.png`）
   — 條列它要的三個權限（剪貼簿 / 裝置方向 / 媒體音量）並各自說明用途，
     最後一句是「语燕输入法不搜集、上传、分析用户任何信息」。
2. `启用输入法` 按鈕 → 系統輸入法設定（`yuyan/03-after-consent.png`）
3. `选择输入法` 按鈕 → 系統輸入法選擇器（`yuyan/06-setup-final.png`）

**發現的缺陷**：我用 `adb shell ime set` 把它設成預設之後，精靈**仍然停在第 3 步**，
一定要從它自己的按鈕叫出選擇器再點一次才會過關。也就是說它的「已完成」判定
不是查系統狀態，而是記自己的旗標。使用者若從系統設定裡先設好，會被困在精靈裡。

「安裝即用」的實際體感來源不是這三步，而是——

### 4.2 鍵盤內 12 宮格快捷面板（點左上角鳥 logo）

`yuyan/32-logo-menu.png`，4 欄 × 3 列：

| | | | |
|---|---|---|---|
| 切换键盘 | **键盘高度** | 剪贴板 | 深色模式 |
| 按键效果 | **单手模式** | **数字行** | 繁体输入 |
| 双拼辅助 | **悬浮键盘** | 花漾字 | 设置 |

**「键盘高度」是原地拖曳把手 + `重置` / `确认` 兩顆按鈕**（`yuyan/61-kbd-height.png`），
不跳頁、不跳滑桿，拖完就是最終樣子。這是整個 App 裡最好的一個互動。

**「数字行」打開後**（`yuyan/60-numberrow-on.png`）：九宮格上方多一列 1–0 的**矮列**，
而且**底列的 `123` 鍵自動消失**（6 鍵變 5 鍵）——因為數字已經常駐了。
這種「加了 A 就自動收掉 B」的自適應，我們現在完全沒有。

### 我們現在贏在哪（使用者為什麼選我們）

1. **臺灣正體 + 注音大千是一等公民**，不是「簡體輸入法加一個繁體開關」。
   語燕的「繁体输入」是 OpenCC 後處理；我們是 `luna_pinyin_tw` / `bopomofo_tw` 方案。
2. **真 librime + 方案市集**：`t9_pinyin`、`bopomofo_tw` 都是可替換的 schema，
   語燕的九宮格是寫死的 Java 邏輯。fcitx5 也有 rime 外掛，但要另外裝一顆 APK。
3. **零權限、資料全在 app 私有目錄**。Trime 那個「所有檔案存取權」是勸退點；
   語燕要剪貼簿/感測器/音量三個權限。
4. **四端同源**（本專案定位），語燕只有 Android。
5. **啟動即用**：`首次部署耗時 8359 ms`，之後直接可打；Trime 連第一次都起不來。

### 我們現在輸在哪（照嚴重度排）

1. 九宮格少一欄、少分詞、少重輸、底列只有 3 鍵。
2. 沒有工具列，沒有剪貼簿，沒有 emoji/顏文字。
3. 符號層形狀跳變（4 欄 → 10 欄）。
4. 沒有任何鍵盤外觀/高度/單手的使用者可調項。
5. 沒有按鍵回饋（氣泡、長按副符號）。

## 7. 我認為我們該改什麼（依優先序）

### P0-1　九宮格補成 5 欄，並補上「分詞 / 重輸 / 0」

**依據**：三星實機照片 `samsung/photo_1_*.jpg` 與語燕 `yuyan/46-after-close.png`
**兩個獨立來源同時是 5 欄、同時把「分词」放在 1 位、同時有「重输」**。
兩家在同一件事上巧合的機率極低，這是九宮格的既定慣例。

具體：
- 新增第 1 欄（標點）：`,` `。` `?` `!` — 可採三星的四顆獨立鍵，或語燕的
  「一顆跨 3 列高鍵 + 鍵面直排」。**建議跟語燕**，因為那顆高鍵在打字時
  可以整欄換成別的用途（見 P1-1），四顆獨立鍵就沒這個彈性。
- 「1」位改成 **分詞**（送 `'`，這正是我們現在放在那裡的字元，只是換個鍵面
  與名字；`core/layouts/t9-pinyin.yaml` 的 label/hint/send 三分離剛好支援）。
- 第 5 欄改成 `⌫` / **`重输`** / `0`，`中`、`符` 移到底列。
- 底列補成 5–6 鍵：`符` · `☺` · `123` · `␣` · `中` · `↵`。

**副作用（正面）**：字母鍵寬會從 251px 降到約 200px，
鍵寬:鍵高從 **1.92:1 回到約 1.5:1**，與三星的 1.53:1 對齊（§5.2）。

### P0-2　把「符 / 123」層做成 5×4，不要跳回 10 欄

**依據**：`ours/31-t9-symbol.png` vs `yuyan/50-numeric-layer.png`。
我們從 4 欄跳到 10 欄，語燕維持 5×4（左欄 `% / - + *`、1–9、右欄 `⌫ . @`、
底列 `符号 ☺ 返回 0 ␣ ↵`）。九宮格使用者是**單手拇指**，欄數一變手就要重新定位。
語燕連「返回」鍵都特地做出來，就是知道使用者會在兩層之間來回。

### P0-3　統一鍵高，取消底列矮 40px

**依據**：§5.3 實測。我們 QWERTY 列節距 154px、九宮格 162px、底列又矮 40px。
語燕四種佈局一律 152px 鍵高 + 28px 鍵距。
建議先統一成一個 token（例：鍵高 47dp、垂直鍵距 12dp、列節距 59dp），
兩種佈局共用，底列不例外。

### P1-1　T9 打字時左欄變「拼音消歧欄」

**依據**：`yuyan/52-t9-candidates.png`、`yuyan/53-candidates-expanded.png`。
沒打字時左欄是標點；一開始打字就換成候選音節（`mi / ni / m / n / o`）。
這比 `分詞` 更早介入，能大幅降低 T9 的模糊度。
我們的 `t9_pinyin` schema 用 `ADGJMPTW` 代表字母，前端拿得到 preedit，
要做這件事在架構上是通的。

### P1-2　加一條工具列（撤銷 / 重做 / 游標 / 剪貼簿）

**依據**：四家都有。fcitx5 的最精簡也最好抄：
`‹ · ↶ · ↷ · ⇔(游標) · 📋 · ⋯ · ▾`（`fcitx5/11-menu.png`）。
語燕是 `logo · ⇔ · ☺ · 📋 · ∨`（`yuyan/30-t9-pinyin.png`）。
我們現在候選列左端只有一顆 ⌨（開方案選單），右邊全空。

### P1-3　鍵盤內快捷面板 + 拖曳式鍵盤高度

**依據**：`yuyan/32-logo-menu.png`、`yuyan/61-kbd-height.png`。
語燕「安裝即用」的體感就來自這個 12 宮格面板——切鍵盤、調高度、開數字行、
單手、深色，全部不離開鍵盤。**「鍵盤高度」用原地拖曳把手 + 重置/確認，
比任何設定頁的滑桿都直觀**，強烈建議照抄這個互動。

### P1-4　符號層分類 + 最近使用

**依據**：`samsung/photo_3_*.jpg`（△▽ 翻頁 + 中/英兩類）、
`yuyan/40-symbols-p1.png`（中文/英文/数学/其他/emoji/顏文字/⌫ 七頁籤 +
頂部橫向「最近使用」列）。我們現在只有 `#+=` 一頁。
建議走語燕的捲動 + 頁籤（比三星的 △▽ 翻頁好，翻頁要記得自己在第幾頁）。

### P2-1　按鍵預覽氣泡（可關）與 QWERTY 副符號

**依據**：語燕「按键气泡」設定項預設開；QWERTY 每顆字母鍵左上角有副符號，
配合設定裡的「上划选择符号」用上滑手勢輸入（`yuyan/34-quanpin.png`）。
fcitx5 是把副符號印在字母**下方**（`fcitx5/10-qwerty.png`）。
我們的 layout 格式已有 `hint`，可以直接掛。

### P2-2　剪貼簿

**依據**：三星有分類頁籤（全部/地址/電話/網站/電子郵件，`samsung/photo_6_*.jpg`）；
語燕有歷史上限、提示超時、單/多列版面。四家都有，我們沒有。
但這需要一個持久化層與隱私決策，所以排 P2。

### P2-3　方案選單去掉 schema id

**依據**：`ours/25-schema3.png` 右側印著 `luna_pinyin_tw` / `t9_pinyin`。
三星與語燕都只給圖示 + 中文名（`samsung/photo_5_*.jpg`、
`yuyan/33-switch-keyboard.png`）。建議把 id 收進「診斷」頁。

### P3-1　把底部 75px 手勢導覽帶做成可用區

**依據**：語燕的「全面屏键盘优化」（`yuyan/21-fullscreen-opt.png`）——
左功能鍵 / 右功能鍵 / 中間快速移動游標，三個都可指派。
我們現在那 74–75px 是空的（`ours/10-qwerty.png` 底部）。
這是純賺的螢幕空間，但要小心與系統手勢衝突，所以排 P3。

### 明確**不建議**抄的

- **語燕的「花漾字」**（把輸入的字轉成裝飾字體）：與「臺灣正體、正確排版」的
  產品定位相反。
- **語燕的手寫**：那是 `libSogouShell.so` + 搜狗模型，授權與體積（單這一塊
  就 ~15MB assets）都不划算。
- **Trime 把使用者目錄放外部儲存**：這正是它跑不起來的原因，是反面教材。
