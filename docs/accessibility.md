# 無障礙(Android)

## 現況

鍵盤是自繪的:一顆鍵就是一個畫著字的 Box。在這一輪之前,全專案 0 個
`contentDescription`、0 個 `semantics` —— TalkBack 摸到的是一塊念不出來的方格。

現在每一顆鍵、工具列的每一項、候選列的每一個候選字都有:

- **朗讀名**(`contentDescription`)。規則在 `keyboard/KeyA11y.kt`(純函式),
  字在 `res/values*/strings.xml` 的 `a11y_*`。切開的理由與 PrefLevels／PrefLabels
  相同:規則要能被 JVM 測試掃過十二份佈局的每一顆鍵。
- **狀態**(`stateDescription`)。中／En、繁／简、全形／半形這幾顆狀態鍵,
  名字說它切換什麼,狀態說現在停在哪 —— 狀態變了 TalkBack 會重念,
  使用者才知道自己按成功了沒有。
- **動作**(`onClick` / `onLongClick`)。見下一節。

## 為什麼「補了名字」還不夠

⚠ 這是這件事最容易只做一半的地方,而做一半的結果不是「無障礙不夠好」,
是一顆**念得出名字、聚焦得到、輕點兩下什麼都不會發生**的鍵。

原因:`KeyView` 的觸發整段都在 `pointerInput` + `detectTapGestures` 裡,
而 TalkBack 的「輕點兩下」送的是無障礙的 `ACTION_CLICK`,**不會**變成
pointer 事件。所以語意節點必須自己帶 `onClick`,而且要接到**同一個**
`fire()`,不能另外寫一條會漂移的路徑。

這與本專案抓過的重輸鍵、中英鍵、表情鍵是同一類缺陷,只是這一次只有用
TalkBack 的人碰得到,所以更不會有人回報。

## 自動化守得住什麼

`KeyA11yTest`(5 條,每一條都用植入違規實測過會紅):

- `core/layouts` 每一份、每一層、每一顆非 spacer 的鍵都算得出名字;
- 工具列每一項都算得出名字;
- 出貨的佈局／主題用到的每一個語義圖示都有朗讀名(漏一個就會去念替代字形);
- 有行為的鍵都要求了對應的語意動作;
- `KeyView` 真的把 `onClick` 接到 `fire()`、`onLongClick` 接上長按與彈出盤、
  並宣告了 `Role.Button`。

## 自動化守不住什麼(必須由人做)

**用 `adb shell input` 驗不了 TalkBack。** 實測過:開著 TalkBack 與探索觸控,
從 adb 送出的 tap 與 swipe **繞過了無障礙的輸入過濾**,直接被鍵盤當成一般
觸控吃掉 —— 送三次「向右滑」(TalkBack 的「下一個項目」)之後,輸入框裡多了
`sss`,焦點框一次都沒有出現。

`uiautomator dump` 也不行:它只 dump 前景 app 的視窗,而鍵盤是
`TYPE_INPUT_METHOD` 的另一個視窗(`dumpsys accessibility` 看得到它確實對無障礙
曝光了,但 dump 不出它的節點樹)。

所以下面這幾件事**只有人做得到**,請在真裝置或模擬器上手動走一次:

1. 設定 › 無障礙 › TalkBack 開啟,回到任一輸入框叫出鍵盤。
2. 逐鍵探索:每一顆鍵都要念出**它做什麼**,不是它長什麼樣。
   - `⌫` 要念「退格」,不是「叉叉」;
   - 地球鍵要念「選擇鍵盤」,不是「地球」;
   - `?123` 要念「切換到 符號」(目標層自己的名字),不是「問號一二三」;
   - 中／En 要念「中英切換」並接著念目前是「中文」還是「英數」。
3. **每一顆都輕點兩下**,確認真的做了它宣稱的事。這一步不可以只抽驗幾顆 ——
   本專案抓到的五顆死鍵全部都是「畫面正常、自動化全過」。
4. 切到英數模式、切到九宮格、進符號面板,各重複一次第 2、3 步:
   狀態鍵的 `stateDescription` 要跟著變。

## 還沒做的

- **鍵盤上的設定面板**(`KeyboardPanels.kt`)的格子與分段控制還沒有語意層。
  它們用的是 `clickable`,所以動作是通的、也念得出格子上的字,但沒有
  「目前選取的是第幾格」這種狀態描述。
- 候選列的翻頁與長按刪詞還沒有對應的無障礙動作。
- 一個能讀 IME 視窗節點樹的 instrumentation 測試(UiAutomator)。那會把上面
  第 2 步變成自動的;第 3 步仍然需要人。要新增 androidTest 相依,涉及取用
  網路,所以先提出來而不是直接做。
