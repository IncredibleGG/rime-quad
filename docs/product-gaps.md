## 1. 基準線:麻瓜的第一小時

### 1.1 為什麼用「第一小時」而不是功能表

功能表會產生一份 60 項的清單,而 60 項的清單沒有辦法排序 —— 每一項看起來都很合理。
「第一小時」給的是**順序**:使用者是照這個順序撞到問題的,而**他撞到第一個
過不去的關卡就停在那裡了**,後面 50 項做得再好他也看不到。

所以下面十個時刻是有先後的。**排序的第一原則是:先修早發生的那一個。**

### 1.2 十個時刻

| # | 他在做什麼 | 他理所當然的期待 | 少了會說什麼 |
|---|---|---|---|
| 1 | 裝完,去系統設定裡找 | 清單上有一個看得懂的名字和一個圖示 | 「裝了但找不到」 |
| 2 | 選了它,回到剛剛那個輸入框 | 打得出中文 | **「這東西不能用」** |
| 3 | 打了一句 | 出來的是他要的那種字(繁/簡) | **「打出來是亂七八糟的字」** |
| 4 | 句子中間要打一個英文單字 | 有一個地方按一下就切英文 | **「我沒辦法打英文」** |
| 5 | 想知道自己現在是中文還英文 | 螢幕上某處看得到 | 「我不知道它現在怎麼了」 |
| 6 | 打錯了 | 退格、重打、翻頁選字 | 「刪不掉」 |
| 7 | 想調一點東西(字大一點、換方案) | 找得到設定,而且看得懂 | 「這是給工程師用的」 |
| 8 | 打了半小時 | 它記得住他常用的詞 | 「它學不會」 |
| 9 | 想打個表情 / 貼上剛複製的東西 | 有 | 「少一個功能」 |
| 10 | 換一台電腦或手機 | 詞跟著走 | 「我要重來一次」 |

**分界線在第 8 與第 9 之間。** 1–8 是「輸入法」這個東西的定義,9–10 是加分。
競品在 9–10 上做得很滿(剪貼簿、表情、皮膚、雲同步),**那不是我們現在該追的地方** ——
我們有 1–8 還沒補完的洞。

### 1.3 慣例的判定(兩家以上才算)

只列與 1–8 有關的。**每一格標來源等級。**

| 事情 | 行動端 | 桌面端 | 算不算慣例 |
|---|---|---|---|
| 一顆隨手可及的**中/英**切換 | Gboard / 三星 / 語燕底列都有「中/英」鍵 **(測)**;搜狗、百度、微信鍵盤同 **(查)** | 微軟拼音工具列第一格是中/英 **(查)**;搜狗狀態列第二格是「輸入狀態」**(查)**;小狼毫托盤圖示畫的就是中/英 **(查)** | ✅ **是。四家以上,兩個形態都是** |
| **看得到現在是什麼模式** | 鍵盤上那顆鍵自己就顯示 **(測)** | 微軟拼音、搜狗、小狼毫都有一個常駐可見的指示 **(查)** | ✅ **是** |
| 一顆隨手可及的**簡/繁** | 語燕做成設定項不是鍵 **(測)**;搜狗手機端在鍵盤面板裡 **(查)** | 搜狗狀態列可設預設簡繁 **(查)**;小狼毫用 `zh_simp` 開關 + 托盤 **(查)**;微軟拼音有簡繁熱鍵 **(查)** | ⚠ **桌面是慣例,行動端不是** |
| **方案 / 輸入方式**切換入口 | 三星工具列 ⌨、語燕 12 宮格面板 **(測)** | 小狼毫/鼠鬚管是 `Ctrl+\`` + 托盤選單 **(查)**;搜狗狀態列的 S 選單 **(查)** | ✅ **是** |
| **設定**入口 | 都有 **(測)** | 都有 **(查)** | ✅ **是** |
| 全/半形、中/英標點 | 幾乎不在鍵盤上 **(測)** | 搜狗、微軟拼音的狀態列有 **(查)** | ⚠ **只在桌面,而且是老習慣**(見 §4.1) |
| 表情面板 | 四家都有 **(測)** | 微軟拼音工具列有 **(查)**;小狼毫/鼠鬚管沒有 **(查)** | ⚠ **行動端是慣例,桌面端不是** |
| 剪貼簿歷史 | 四家都有 **(測)** | 系統自己有(Win+V) **(查)** | ⚠ **行動端是慣例;桌面端系統已經給了** |
| 詞庫匯出匯入 | 語燕有「导出/导入用户数据」**(測)** | RIME 系是「把 `%APPDATA%\Rime` 整個複製走」**(查)** | ✅ **是,但形態不同** |
| 圖形化設定 | 都有 **(測)** | 微軟拼音/搜狗有;**小狼毫/鼠鬚管沒有 —— 那正是中州韻助手 rimetool 存在的理由 (查)** | ✅ **是,而且是 RIME 系最大的劣勢** |

**這一格值得單獨講:圖形化設定。**
小狼毫與鼠鬚管把設定留在 YAML 檔裡,於是社群長出了 rimetool / 小狼毫助手
這種第三方 GUI 來補 **(查)**。使用者評語裡最常出現的詞是「勸退」「要懂一點程式」**(查)**。
**我們桌面兩端已經有原生的圖形化設定介面,這是我們相對於整個 RIME 系最大的優勢**,
而它現在被「Windows 沒有中英切換」這種第 4 個時刻的洞抵銷掉了。

## 3. 我們現在贏在哪(排序時不要把這些拆掉)

盤點缺口容易變成「什麼都要補」。下面五項是**已經成立、而且競品做不到**的,
任何一項優先序的調整不可以傷到它們:

1. **臺灣正體與注音大千是一等公民**,不是「簡體輸入法加一個繁體開關」**(測)**。
2. **零權限、資料全在私有目錄**。同文 Trime 要「所有檔案存取權」而且因此起不來 **(測)**;語燕要三個權限 **(測)**。
3. **離線為預設,而且可被外人稽核**:單一連網出口、連網紀錄、開關預設關閉,
   Windows 端甚至驗到「產物的匯入表裡沒有網路 DLL」。
4. **桌面端有原生圖形化設定** —— 小狼毫/鼠鬚管沒有,社群要靠 rimetool 補 **(查)**。
5. **四端同源的主題與佈局格式**。語燕的九宮格是寫死的 Java 邏輯 **(測)**。

## 4. 使用者這一輪點名的項目(逐條)

### 4.1 Windows 需要一個浮動狀態列

> 使用者原話:「小小一橫在右下角,可以拖動,上面可以快捷修改」。

#### 4.1.1 這不只是體驗問題:Windows 端**根本沒有中英切換**

我原本以為這是「多一個方便的入口」。讀了碼之後不是。**(碼)**

```
windows/service/engine.cc:31        if (s.is_ascii_mode) f |= kStAsciiMode;   ← 唯一一處
windows/common/protocol.h:163       kStAsciiMode = 1u << 1;                   ← 唯一一處
```

`ascii_mode` 在整個 `windows/` 底下只出現在這兩行,**都是「回報狀態」,
沒有任何一處設定它**。而三條可能的路全部不通:

- **Shift** —— TSF 不把純修飾鍵交給 key event sink(`tsf/text_service.cc:549`)。
- **語言列按鈕** —— 只有一顆「設定」,`InitMenu` 回 `E_NOTIMPL`,刻意不做選單。
- **系統匣右鍵選單** —— 有「設定 / 簡繁三態 / 重新整理字詞 / 結束」,**沒有中英**。

也就是說:**一個 Windows 使用者要在句子中間打一個英文單字,唯一的辦法是
按 Win+空白鍵把整個輸入法換掉,打完再換回來。** 這是時刻 4,而時刻 4
在 §1.2 的分界線上面。

⚠ 所以「Windows 的 Shift 切英文沒有作用」這條使用者回報,**修法不是去修 Shift**。
Shift 那條路要掛低階鍵盤 hook 才做得到,而低階 hook 在一個以「經得起審計」
為定位的產品上是很貴的東西(它會看到使用者的每一次按鍵,包括別的程式裡的)。
**浮動狀態列是同一個問題成本低得多的解。**

#### 4.1.2 上面該放哪幾個東西

先看對照組 **(查)**:

| | 項目 |
|---|---|
| 搜狗(PC) | S 選單 · **輸入狀態(中英)** · 全/半角 · 中/英標點 · 通行證 · 軟鍵盤 · 設定 |
| 微軟拼音(Win11 輸入法工具列) | **中/英** · 全/半角 · 中/英標點 · 表情 · 設定 |
| 小狼毫 | 沒有可拖動的狀態列。只有托盤圖示(畫的是中/英)+ 切換時短暫的狀態提示,`style/display_tray_icon` 可關 |

三家的交集只有兩項:**中/英** 與 **設定**。

再看我們自己的規範。`docs/theme-format.md` §8.12 的**規範性預設清單**是:

```yaml
items:
  - { source: schema_name,     tap: "schema:picker" }
  - { source: input_mode_pair, tap: "input_mode:toggle" }
  - { source: variant,         tap: "toggle:simplification" }
  - { source: page }
```

兩條獨立的線索指向同一組東西。**建議放四格:**

| 格 | source | 為什麼是它 |
|---|---|---|
| **中/En** | `input_mode_pair` | §4.1.1:這是把一個**做不到**變成做得到,不是把做得到變好看。而且 §8.12 已經裁決字面是 `中`/`En`、兩態同時顯示(只寫一個「中」有兩種讀法,Android 被真機回報過) |

**明確不要放,以及為什麼:**

- **全/半形、中/英標點** —— 對應 `text.shape` / `text.punctuation`,預設都是
  `followSchema`。搜狗和微軟拼音放它們,是因為它們的使用者裡有大量從
  Win95 一路用過來的人;麻瓜一輩子不會動這兩項。每多一格就多一個
  「按了看不出差別」的面。
- **表情** —— 我們四端都沒有表情面板。放上去就是第七顆「看得到摸不到」。
- **軟鍵盤、通行證(帳號)** —— 前者沒有,後者**刻意永遠不會有**。

#### 4.1.3 ⚠ 這條會撞到規範,而且不是小事

**使用者要的東西不是 §8.12 的 `status_bar`。**

§8.12 的狀態列**住在候選窗裡面**,而且它自己寫著:「桌面端沒有工具列……
桌面端的等價物是 IMKit / TSF 提供的輸入法選單」。候選窗只在組字時出現 ——
**不打字的時候使用者什麼都看不到**,而使用者要的正是「隨時看得到、
可以拖到他喜歡的位置」的那一橫。

所以這是一個**規範沒有的新表面**,不是把 §8.12 打開就好。三件事要先決定:

1. 它要不要進 `docs/theme-format.md`(規範所有權在 macOS 端),還是先宣告成
   Windows 平台專屬。**建議進規範** —— macOS 的選單列圖示是同一個問題的
   另一半,兩端各自發明會長成兩個東西。
2. `source` 的字面必須沿用 §8.12(`中`/`En`、`简`/`繁`),否則同一個產品的
   兩個表面會顯示不同的字。
3. §8.12 末段已經記著一個**還沒關的缺口**:「`source` 全是文字、沒有圖示」,
   並明寫「在補上之前不要自己發明」。一橫狀態列上四格純文字是可行的
   (搜狗的「中」也是文字),**所以不必等那個缺口,但也不可以順手加圖示**。

### 4.2 Windows 選了輸入法之後有時候打不出中文

**這是本文件最重要的一格,而且它的成因與「有時候」這個詞高度吻合。(碼)**

`windows/common/link_state.h` 的檔頭寫著一條刻意的不變式:

> **只有在確定拿得到服務進程的回覆時,才可以吃掉按鍵。**
> 其餘每一種狀態 —— 沒連上、握手版本不合、逾時、對面崩了、解碼失敗、
> 序號對不上 —— 一律放行。

這條設計是**對的**(輸入法吃掉按鍵 = 使用者的電腦不能打字,比沒作用嚴重一個等級),
但它的副作用正是使用者看到的症狀:**每一種失敗都長成「打出英文字母」,
而且畫面上完全正常。** 已知會走到這條路的至少五種:

| 情形 | 碼 |
|---|---|
| 服務還沒起來 / 起不來 | `LinkFailure::kConnectFailed` |
| 冷啟動時第一次建 session 超過 300ms 預算 | `kTimeout`。已用 `service/main.cc` 的 `WarmUpEngine` 緩解,但**只預熱預設方案** |
| DLL 與服務版本不合(升級後宿主還開著舊 DLL) | `kHandshake` / `kPeerClosed` |
| 提權宿主(以系統管理員執行的程式) | `elevation_policy` **刻意不啟動服務** |
| 對面崩了 | `kIoError` |

⚠ **使用者唯一看得到的訊號是語言列按鈕上那四個字「未啟動」**
(`tsf/lang_bar.cc:28`),而那顆按鈕在 Win11 上多半收在輸入指示器裡,
**要點兩下才看得到**。`lang_bar.cc` 自己的註解已經寫得很清楚:
「一個**刻意的**拒絕不該長得跟壞掉一樣」。這個判斷是對的,問題是那四個字
的曝光度不足以承擔它的責任。

**所以這一條與 §4.1 是同一件事的兩半:浮動狀態列同時是「中英切換」的家,
也是「未啟動」這個訊號唯一夠顯眼的家。** 兩件事一起做的成本遠低於分兩輪。

⚠ **不要把這一條的修法寫成「調大逾時預算」。** `ipc_client.cc:456` 已經
分析過:`EnsureReady()` 跑在宿主的 UI 執行緒上,調大等於讓使用者按下第一顆鍵時
整個程式卡住那麼久 —— 那不是修好,是換一種壞法。

### 4.3 Windows 的 Shift 切英文沒有作用

見 §4.1.1。**這條的正確結論是「Windows 端沒有任何中英切換」,Shift 只是
三條不通的路裡的一條。** 直接修 Shift(掛低階鍵盤 hook)在成本與定位上都不划算:
低階 hook 會看到使用者在**每一個程式**裡的每一次按鍵,而我們的賣點是可稽核。

### 4.4 Android 九宮格缺拼音消歧欄

✅ 已確認缺席 **(碼)**:`core/` 與 `android/` 底下沒有任何 syllable / 消歧相關的東西。

上一輪的實機量測 **(測)** 記錄了語燕的做法:沒打字時左欄是標點,一開始打字
就整欄換成候選音節(`mi / ni / m / n / o`)讓你點。`docs/competitive-review.md`
§3.3 的原話是「這是讀原始碼絕對想不到的互動,也是九宮格能不能用的關鍵」。

⚠ **但這一輪我要對那個判斷打一點折扣。** 五欄改造(task #30)已經落地,
而五欄同時帶進了**分詞鍵**——分詞是消歧的手動版本。消歧欄是「系統主動列出可能」,
分詞是「使用者手動切開」。兩者解同一個問題,只是主動與被動之別。
所以消歧欄現在是「讓 T9 好用很多」而不是「讓 T9 可用」。這影響它的排序(見 §5)。

**這條屬於另一條線(task #31),本文件只做排序,不指定做法。**
